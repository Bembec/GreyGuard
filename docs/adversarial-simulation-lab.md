# Non-operational adversarial simulation lab

GreyGuard Section 14 represents prohibited behavior only through predefined synthetic defensive scenarios. The lab is disabled by default, uses fictional `.example` targets, accepts scenario identifiers rather than commands or code, imports no production executor, and has no filesystem, process, secret, device, or network capability.

Every run is immutably marked `simulated: true`, produces BLOCK or REFUSED, adds synthetic risk, raises a synthetic alert, preserves evidence, recommends analyst response, states hypothetical impact without operational instructions, confirms no real action executed, and resets automatically.

The catalogue covers simulated keylogging, credential harvesting, browser-token theft, process-memory access, covert capture, unrestricted collection, arbitrary shell, unauthorized egress, persistence, control bypass, malware/rootkit deployment, ransomware, flooding, hack-back, external destruction, unconnected-agent surveillance, audit deletion, and self-modification/evasion.

Administrators can disable the entire lab immediately. Removal consists of disabling it, preserving required simulation evidence, removing the simulation route/module/page, and rerunning core policy, audit, and navigation tests.
